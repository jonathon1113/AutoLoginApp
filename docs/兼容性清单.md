# 兼容性清单（Selenium → Playwright 重构）

本清单逐项对照重构前项目（`login_gui_pyqt6.py`，PyQt6 + Selenium）与重构后项目
（`main.py` + `appcore/` + `appui/`）的功能、参数、配置、资源与操作方式。

标注说明：
- **保留**：名称、语义、默认值、格式、交互方式均未改变。
- **保留（实现替换）**：用户可见行为一致，底层实现由 Selenium 换成 Playwright。
- **修正**：原项目缺陷，重构时修复并在《变更说明》中列出。
- **删除**：随框架迁移不再需要的代码，已在《变更说明》中说明原因。

## 5. 行为差异说明（均为迁移所必需或缺陷修正）

| 差异 | 原因 | 影响范围 | 处理方式 |
|------|------|---------|---------|
| 登录成功判定由「点击登录按钮即成功」改为「表单消失 / URL 变化 / 出现错误提示」 | Selenium 版存在误报（点错按钮也算成功） | 所有登录流程 | 成功判定更严格，界面提示更真实；不改变操作方式 |
| 固定 `time.sleep` 全部替换为自动等待 / 状态等待 | 任务书要求 | 全流程 | 速度更快更稳定，无功能删减 |
| SSL 处理由「跳转百度再跳回原 URL」改为 `ignore_https_errors` + interstitial「高级/继续」点击 | 原实现会丢失页面状态且有外部依赖 | HTTPS 站点 | 行为更安全，无外部网络依赖 |
| 选择器 `by` 语义保留但底层改为 Locator | Playwright 无 `By` 常量 | 模板文件 | 模板文件无需修改，历史模板继续可用 |
| `template_recorded` 信号类型由 `pyqtSignal(str, str)` 改为 `pyqtSignal(str, object)` | 原项目发射的是 dict，类型不匹配会导致「保存模板」回调不触发 | 保存模板 | 修正（原缺陷） |
| `stat_label.setFont = ` 误写为赋值改为 `setFont()` | 原项目笔误 | 界面 | 修正（原缺陷） |
| `login_batch.py` 原读取加密配置不解密 | 原缺陷 | 命令行批量登录 | 改用 `appcore.devices.load_devices`（自动解密） |
| 分组登录的「登录中」过程行不再写入 `login_logs` 表，且单设备记录回填设备名与 URL | 原实现的进程行用 `"成功" in msg` 判定状态，导致单设备记录一律记为「失败」且设备名/URL 为空 | 分组批量登录的数据库日志 | 修正（原缺陷）：过程行只上屏不入库，结果行按 `✓/✗` 前缀记录正确状态、设备名与 URL |
| 退出时增加「关闭线程池 → 关闭全部浏览器 → 停止 Playwright 驱动」完整清理 | 任务书要求 | 退出流程 | 原为直接退出，可能残留浏览器进程 |
| Playwright 浏览器路径 | Selenium 依赖外部 ChromeDriver | 打包 | `PLAYWRIGHT_BROWSERS_PATH=0`，浏览器随 EXE 内置 |
| 默认模板由「仅内存常量」改为「磁盘真实文件 `templates/default.json`」 | 任务书要求默认模板真实存在于磁盘 | 模板系统 | 首次启动创建 `default.json`/`proxmox.json`/`huawei.json`（仅在缺失时创建，不覆盖用户修改） |
| 模板查找顺序改为「先模板、后通用」 | 原实现中通用回退与模板查找混在同一函数，无法区分命中来源；且 `login_button_selectors` 从未被使用 | 所有登录流程 | 模板完全命中时不再执行通用扫描；模板选择器失效时只对失效项回退 |
| 模板名不存在时不再静默套用默认模板 | 原 `get_template()` 找不到时直接返回默认模板，拼写错误被掩盖 | 登录流程 | 返回 `None` 并记录原因，由登录引擎显式回退到内置通用模板 |
| 模板录制记录「实际生效」的选择器（含通用回退命中的情况） | 原实现只在模板命中时记录，录到的永远是默认模板选择器 | 登录模板 | 通用查找命中时同样记录，保存的模板能真正复现 |
| 模板加载增加校验与损坏隔离 | 原实现 JSON 解析失败仅记日志、仍保留半成品注册表 | 模板系统 | 致命错误跳过该文件并记录原因；警告级问题仍可加载；单个损坏文件不影响其它模板 |
| 模板保存增加名称校验、原子写入与回读校验 | 原实现直接 `open(...,'w')` 覆盖写，中途失败会留下损坏文件 | 模板系统 | 临时文件 + `os.replace` 原子写入，写后回读校验，失败返回 False 且不留半成品 |
| 模板录制状态改为按线程隔离 | 原实现为类级单一变量，并发登录会互相覆盖 | 快捷/分组登录 | 按线程隔离 + 最近一次结果槽 |
| 模板目录不随 EXE 内置 | 用户模板必须落在可写目录，否则重启即丢失 | 打包与运行 | 模板目录固定为可写数据目录下的 `templates/`（EXE 同目录 / 源码根目录） |
| 登录日志新增 `[LOGIN_SUMMARY]` 汇总行 | 原实现只有分散的单点日志，无法确认最终实际使用的模板 | 所有登录流程 | 每次登录输出含设备 / 入口 / 任务 ID / 配置模板 / 实际执行模板 / 模板文件绝对路径 / 是否回退 / 最终结果 / 分段耗时的汇总行，三个入口统一 |
| 保存模板提示改为统一规则判断 | 原实现用选择器列表全等比较判定“相似模板”，几乎恒为假，且不看设备配置的 `template` 字段 | 保存模板 | 新增 `evaluate_save_template_request()`，区分「存在 / 匹配 / 可加载 / 执行成功 / 需要保存」，已有可用模板时不再提示新建 |
| 已有模板的保存改为覆盖确认 | 原实现一律按新建模板提示 | 保存模板 | 目标模板已存在时进入「更新 / 覆盖确认」流程，用户取消则磁盘文件保持不变 |
| 选择器查找由「每候选各自等待复查窗口」改为「每候选一次毫秒级存在性检查 + 页面级延迟渲染窗口」 | 原实现为每个不存在的候选付出 0.15~0.5s 等待，18 个候选会在第 7 个处耗尽 2.5s 预算，剩余候选从未执行 | 所有登录流程（用户名 / 密码 / 登录按钮） | 整份候选列表都能在预算内被真正执行；命中耗时由 2.7s 降到 45~1094ms |
| 新增逐候选诊断日志与查找汇总日志 | 原实现只有一句「剩余 N 个候选未尝试」，无法核验每个候选的耗时与去向 | 所有登录流程 | 每个候选输出序号 / 选择器 / 结果 / 耗时 / 剩余预算；每次查找输出候选总数 / 已执行 / 未执行 / 分类耗时 / 退出原因 |
| 查找失败原因不再统一归为 `form_not_found` | 原实现把 `budget_exceeded` 也转成 `form_not_found`，真实原因丢失 | 失败日志与失败原因分类 | 细分为 `selector_not_found` / `budget_exceeded` / `element_not_visible` / `selector_invalid` / `selector_error` / `page_not_ready` / `frame_not_checked` |

## 8. 无法完全兼容的部分

经逐项核对，**没有发现无法兼容的功能**。以下为「无 Playwright 一一对应 API，改用适配实现」的项目，
均已保持用户可见行为一致：

| 项目 | Playwright 无对应 API | 适配实现 |
|------|---------------------|---------|
| Selenium `By.NAME` / `By.ID` / `By.CLASS_NAME` | 无 | 转为 CSS 属性选择器 `[name=…]` / `[id=…]` / `[class~=…]` |
| Selenium `By.XPATH` | 无 | `locator("xpath=…")` |
| `driver.find_elements` 返回列表 | 无 | `locator.count()` + `locator.nth(i)` 遍历 |
| `element.is_displayed()` / `is_enabled()` | 无 | `locator.is_visible()` / `is_enabled()` |
| `WebDriverWait(driver, t).until(readyState=='complete')` | 无 | `page.wait_for_function("document.readyState === 'complete'")` |
| `switch_to.window_handles` 标签页集合 | 无 | 会话内维护 `pages` 列表 + `current_index` |
| `driver.quit()` | 无 | `context.close()` + `browser.close()` |
