# H. 版本 5.0.11 变更（Excel 导入界面未响应修复 + 用户名选择器角色误判修复）

本次变更是**局部修复**：不重构整个项目、不删除现有功能、不关闭任何必要的校验机制。

## H.1 修复：导入约 100 台设备后界面长时间「未响应」

### 根因（基于实际代码与耗时实测，不是按数据量推断）

旧版 `on_import_excel()` 在 **Qt 主线程里同步完成全部导入工作**。
实测 100 台设备的分阶段耗时：

| 阶段 | 耗时 | 占比 |
|------|------|------|
| `openpyxl.load_workbook()` | 31 ms | 0.2% |
| 逐格 `ws.cell()` 遍历 + 校验 | ~0 ms | ~0% |
| **`encrypt_devices()`（PBKDF2 50000 轮 × 200 字段）** | **13 110 ms** | **99.7%** |
| **主线程阻塞合计** | **13 141 ms** | 100% |

Windows 在主线程无响应约 5 秒后即弹出「未响应」，13.1 秒必然触发。

**已排除的怀疑项（有代码证据）**

- `update_device_list()`：一次性 `clear()` + 逐项 `addItem()`；
  `create_group_buttons()`：按分组创建卡片。**不存在「每台设备刷新一次」**。
- Excel 解析本身实测仅 32 ms，不是瓶颈。
- 界面控件创建不涉及复杂控件，也不是瓶颈。

### 修复

- **新增 `appcore/excel_io.py`（纯数据层）**：不 import 任何 Qt；
  负责表头别名映射、必需列校验、`iter_rows(values_only=True)` 流式读取、
  逐行格式校验、重复地址收集、阶段进度回调。
- **新增 `appcore/tasks.py::ImportExcelTask(QRunnable)`**：
  工作线程只做「读文件 → 解析 → 校验 → 加密 → 写盘」；
  **绝不创建 / 修改 / 删除任何界面控件**；
  界面更新一律经 `ImportExcelSignals` 的 queued connection 回到主线程。
- **`appui/main_window.py::on_import_excel()`** 改为启动后台任务后立即返回。
- **`encrypt.py::encrypt_devices()`** 改为 `ThreadPoolExecutor` 并行
  （PBKDF2 在 OpenSSL 实现中释放 GIL，可真正并行）：
  13 187 ms → 4 437 ms（4 核实测 2.97×）。**未改迭代数与密文格式**，
  历史 `devices.json` 仍可正常解密。
- **`appcore/devices.py::save_devices()`** 改为「临时文件 + `os.fsync` + `os.replace`」
  原子写入：导入中途失败时原 `devices.json` 保持不变。
- **进度反馈**：复用已有的 `stat_label` / `progress_label` / `progress_bar`
  （`setRange(0,0)` 忙碌指示，完成后恢复 `setRange(0,100)` 并隐藏）。
- **异常与并发处理**：`_excel_importing` 标志位拒绝重复触发；
  失败时恢复界面并显示**具体原因**（「原有设备配置未被修改。」）；
  窗口关闭时等待导入写盘完成。

### 顺带修正的两处静默缺陷

| # | 缺陷 | 旧行为 | 新行为 |
|---|------|--------|--------|
| 1 | 表头缺 URL 列 | 所有列默认索引都是 1，**静默把第 1 列当 URL**，产出完全错误的数据 | 明确报错并列出实际读到的表头 |
| 2 | 表格中间有空 URL 行 | `break` 直接中断，**后续所有设备被静默丢弃** | 跳过该行并记录原因，其余设备全部导入 |

### 保留的原有行为

Excel 格式兼容性、设备字段映射、分组逻辑、重复设备处理规则（**按原规则全部保留，不去重**）、
无效数据校验、导入结果提示、原有数据保存与持久化行为，**全部保持不变**。

## H.2 修复：用户名选择器被角色校验误判为密码框（`looks_like_password`）

### 根因（基于实际校验逻辑与元素属性）

旧版 `_password_evidence()` 把五类来源**等权**处理，任一命中即返回 2（= 硬性否决）：

| 来源 | 示例 | 旧权重 |
|------|------|--------|
| placeholder / aria-label | `placeholder="请输入密码"` | 2（强） |
| name / id | `name="password"`、`id="pwd"` | 2（强） |
| **class（CSS 类名）** | `class="el-input__inner password"` | **2（与占位符同权）** |
| **autocomplete** | `autocomplete="current-password"` | **2（与占位符同权）** |
| style | `-webkit-text-security` | 2（强） |

同时 `_username_evidence()` **完全不检查 class**，判定不对称。
因此只要账号框**自身**携带上述任一线索，
`placeholder="账号"` 的账号语义**无法抵消**，直接被判 `looks_like_password`。
此外旧实现**没有任何页面级判据**，
无法利用「同一页面另有独立的 `type=password` 输入框」这一事实。

### 修复：证据分级 + 冲突消歧

```
密码证据：强 2.0（placeholder/aria 含密码词、CSS -webkit-text-security）
          中 1.0（name/id 精确密码词）
          弱 0.5（class 含密码词、autocomplete=current-password/new-password）
用户名证据：强 2.0（name/id 用户名词、placeholder/aria 含账号类中文词）
          中 1.0（autocomplete=username/email、type=email）
          （class 不参与 —— 账号框与密码框的类名常常完全相同）
```

判定流程：

1. 结构性否决优先（标签 / type / 隐藏 / 只读 / 禁用 / 不可见）—— 未削弱；
2. 验证码语义优先于密码语义；
3. 密码证据 ≥ 中：同时有强用户名证据 → **证据冲突**，交页面上下文消歧；否则拒绝；
4. 密码证据仅弱 → 放行并记录 `weak_password_signal(...)`；
5. 页面级消歧：同一文档内**存在独立 `type=password` 输入框** → 真密码框另有其物，
   当前文本框按账号处理；**不存在 → 报歧义（`role_conflict`），不盲填**。

### 保留的原有校验

真密码框、验证码框、登录按钮、隐藏域、只读 / 禁用 / 不可见元素的否决规则
**全部保留**，并补充了「多匹配不唯一 → 报歧义」与「证据冲突 → 页面级消歧」。

### 诊断日志（不泄露任何敏感内容）

角色校验失败时输出：目标角色、选择器匹配数、拒绝原因、元素实际
`tag / type / id / name / class / placeholder / autocomplete / aria`、可见性、
密码证据分值与**命中来源**、用户名证据分值与命中来源，
以及最终处置（继续下一个候选 / 报告歧义 / 终止查找）。
**不记录任何表单值**（无账号、密码、验证码）。

# F. 版本 5.0.9 变更（登录速度优化 + 设备分组四列 + 底部居中）

本次变更只涉及**等待策略**与**界面布局**，不删除、不削弱任何原有功能。

## F.1 修复：正常页面登录被「验证码检查」拖慢约 10 秒

### 根因（基于实际代码与实测复现）

| # | 缺陷 | 根因 | 修改文件 |
|---|------|------|---------|
| 1 | 两轮串行超时累积 | 验证码查找分「模板候选 → 内置 `CAPTCHA_SELECTORS`」两轮，每轮各发一份完整 `extra_budget`（`SELECTOR_LOOKUP_SLOW_BUDGET=8.0`），等待成倍累加（实测 9327ms） | `appcore/browser.py` |
| 2 | “无验证码”确认被当成阻塞步骤 | 页面根本没有验证码时，也必须等完整个扩展预算才能提交登录 | `appcore/login_engine.py` |
| 3 | 扩展预算无条件申请 | 慢速路径始终申请 8s 扩展预算，不区分页面是否已就绪 | `appcore/login_engine.py` |
| 4 | 快速检查可能误判 | 表单控件数量尚未稳定时就会判定“无验证码” | `appcore/browser.py` |

### 修复

- `find_captcha_field_detailed()` 引入**共享预算池** `pool`：第一轮用掉多少（`slow_wait_ms`），
  第二轮只能用 `max(0.0, pool - used_extra)`，不再各自拿满。
- 慢速页面的扩展等待收敛为 `SELECTOR_LOOKUP_READY_BUDGET=3.0`，
  并新增 `delayed_window=False` 参数贯穿 `browser.py`，不再无条件申请 8s 扩展预算。
- 新增 `CAPTCHA_QUICK_STABLE_ROUNDS=2`：快速检查需**连续 2 轮表单控件数量稳定**才判定“无验证码”。
- **分级策略**：页面已就绪 → 快速检查；页面未就绪（`loading` / `interactive`）→ 才进入有上限的扩展等待。

### 修复前后实测对比

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 正常页（无验证码）整次登录 | 19093ms | **1297~1672ms** |
| 正常页验证码检查 | 约 10s | 437~796ms |
| 慢速页验证码检查 | 9327ms | **3311~3406ms** |
| 慢速页整次登录 | 13078ms | **6969~7125ms** |

### 未削弱的原有能力

慢速页面等待机制、失败原因分类（`budget_exceeded` / `page_not_ready` / `frame_not_checked` / `selector_error`）、
iframe 检查、逐候选诊断日志与查找汇总、**验证码模板生成绝不自动提交登录**——全部保留。

## F.2 变更：设备分组每行最多 4 张（响应式）

- `GROUP_COLUMNS_MAX = 4`；列数由**滚动区域视口宽度**实时计算并限制在 `1~4`。
- **修复自反馈死循环**：旧实现用容器自身宽度反推列数，容器在 `setWidgetResizable(True)` 的
  `QScrollArea` 内被自身 `minimumSizeHint` 撑大 → 列数不减且卡片被裁切（实测窄 355px 仍为 4 列）。
- 卡片 `minimumSizeHint()` 固定为 `QSize(110, 62)`，长分组名不再撑宽布局。
- 重排前清理旧布局（`QLayout.takeAt()` + `deleteLater()`）并加 `_relayouting` 递归保护；
  新增 `eventFilter()` 监听视口 `Resize`。
- 实测：视口 791 / 594 / 447 / 355 px → 4 / 4 / 3 / 2 列，容器宽度恒等于视口宽度（零裁切、零重叠）。
- 分组名 / 台数 / 双击登录 / 右键菜单 / 设备与分组映射全部不变。

## F.3 变更：底部进度条与浏览器控制按钮整体居中

- 底部改为 `addStretch(1) + footer_content + addStretch(1)`，
  不使用超大 `addStretch()` / 固定宽度 / 空白占位控件把元素推向两侧；
- `progress_bar` 最小宽度 220px（最大 420px），进度文案自动换行；
- 实测：1400px 窗口左右空白 485/485，900px 窗口左右空白 237/235（视觉居中，按钮间距 8px）；
- 「关闭所有浏览器」「关闭浏览器并退出」等按钮及其行为全部保留。

# G. 版本 5.0.8 变更（浏览器黑框与窗口尺寸 + 验证码模板生成 + 慢速页面等待）

## G.1 修复：浏览器启动出现黑框

- 冻结态启动外部进程会弹出黑色控制台窗口（用户看到 `vimc.exe`）；
- 改为**无控制台启动**（`CREATE_NO_WINDOW`），并引入进程级缓存；
  密钥派生结果保持不变，发货代码中不存在其它外部进程调用。

## G.2 修复：浏览器窗口尺寸与页面尺寸不随窗口变化

- 历史版本浏览器以固定小尺寸打开，且 Playwright 默认把视口模拟为固定 1280x720；
- 修复：上下文使用 `no_viewport=True`（页面视口跟随真实窗口），
  新增开关 `BROWSER_START_MAXIMIZED`（默认 `--start-maximized`）。

## G.3 新增：验证码页面的模板生成（生成时绝不自动提交登录）

- 新增 `generate_template_only()`：只在当前登录页识别用户名 / 密码 / 验证码字段并录制，
  **不填写、不点击、不提交**；保存流程与回退规则保持不变。

## G.4 修复：慢速页面等待与失败原因细分

- 页面未就绪等待、延迟渲染输入框检测、iframe 内检查、选择器扫描预算；
- 失败原因分类：`budget_exceeded` / `page_not_ready` / `frame_not_checked` / `selector_error`；
- 诊断预算与逐候选诊断日志、查找结果汇总；登录完成后切回**首个标签页**。

## G.5 新增：五组真实登录页面的识别规则回归

- `tests/test_v508_features.py` 覆盖 q-input / form.userID / UserName+UserPasswd /
  loginName+password+checkCode / Ant Design+Angular 五组真实 HTML 样例的识别规则。

## A.2 问题二：模板库已有模板仍提示保存

### 根因（基于实际代码核查）

| # | 缺陷 | 根因 | 修改文件 |
|---|------|------|---------|
| 1 | 「相似模板」判定几乎恒为 False | 原判定用列表全等比较 `t.get('username_selectors') == recorded.get('username_selectors')`，顺序或内容稍有差异就不相等 → 判定不相似 → 总是弹窗 | `appui/main_window.py` |

  | 模板文件存在但 JSON 无法解析 | 记录具体解析错误，不提示、不覆盖用户文件 |
  | 配置引用的模板不存在 | 记录查找目录与缺失原因，按回退规则处理，允许提示新建 |
  | 未指定模板且现有模板已覆盖选择器 | 不提示 |
  | 目标模板已存在 | 进入「更新 / 覆盖确认」流程，取消则磁盘文件不变 |

- `appui/main_window.py` 新增 `_maybe_save_template()` 统一判断并记录跳过原因；`_show_save_template_dialog()` 改为只做交互（新建 / 覆盖确认 / 取消不写盘）。
- 分组登录改为逐台返回「设备名 + 该设备配置的模板名 + 录制结果」，不再用分组名冒充设备名。

### 根因（基于实际代码与实测复现）

| # | 缺陷 | 根因 | 修改文件 |
|---|------|------|---------|
| 1 | 每个候选都要等复查窗口 | `probe_locator()` 在元素不存在时进入复查轮询：ID/NAME 等满 0.5s、其它 CSS/XPath 等 0.3s，而真正的存在性判断 `count()` 只需 1~30ms | `appcore/browser.py` |

### 修复

- **两阶段查找**：阶段 A 快速扫描（每候选一次不等待的 `count()`）、阶段 B 可见性确认、

  另加子 frame 快速扫描（`SELECTOR_FRAME_BUDGET=0.8s`）。
- **预算语义重定义**：`SELECTOR_LOOKUP_BUDGET` 仍为 2.5s，但约束的是整个查找阶段；
  预算不足时剩余候选逐个记录「未执行」及原因。
- **逐候选诊断日志**：`_format_candidate_log()` 输出候选序号 / 选择器 / 结果 / 耗时 / 剩余预算。
- **查找汇总日志**：`_log_lookup_summary()` 输出候选总数、实际开始执行数、执行完成数、
  因预算不足未执行数、各类候选累计耗时、退出原因、不完整查找标记。
- **失败原因细分**：`selector_not_found` / `budget_exceeded` / `element_not_visible` /
  `selector_invalid` / `selector_error` / `page_not_ready` / `frame_not_checked`。
- **默认模板优化**：用户名候选 18 → 23，`input[type="email"]` 前移到第 2 位；

## 2. 自动化框架迁移（Selenium → Playwright）

### 2.1 浏览器启动

```python
browser = await playwright.chromium.launch(
    headless=False,
    slow_mo=100,
    args=BROWSER_LAUNCH_ARGS,
)
context = await browser.new_context(ignore_https_errors=True)
```

- `headless=False`：保留原项目「有头模式」，用户可见真实浏览器窗口。
- `slow_mo=100`：按任务书要求放慢操作，便于观察自动化过程。
- `BROWSER_LAUNCH_ARGS` 保留原 Selenium `ChromeOptions` 的等价参数
  （`--ignore-certificate-errors`、`--no-sandbox`、`--disable-gpu`、`--disable-web-security`、
  `--disable-blink-features=AutomationControlled`、`--no-first-run` 等）。
- `ignore_https_errors=True` 替代原「访问百度再跳回」触发证书错误的做法（见 §4）。

### 2.2 API 映射

| Selenium | Playwright | 说明 |
|----------|-----------|------|
| `driver.find_element(By.X, v)` | `page.locator(...)` | `to_locator()` 完成 `by/value` → 选择器转换 |
| `By.NAME/ID/CLASS_NAME` | `[name=…]` / `[id=…]` / `[class~=…]` | 属性选择器 |
| `By.XPATH` | `locator("xpath=…")` | 原样支持 |
| `By.CSS_SELECTOR / TAG_NAME` | 直接传 CSS | 原样支持 |
| `element.is_displayed()/is_enabled()` | `locator.is_visible()/is_enabled()` | |
| `element.clear()+send_keys()` | `locator.fill("")` + `locator.fill(text)` | |
| `element.click()` | `locator.click()` | 自带自动等待 |
| `driver.find_elements(...)` | `locator.count()` + `locator.nth(i)` | `iterate_locators()` 封装 |
| `WebDriverWait(readyState=='complete')` | `page.wait_for_function("document.readyState === 'complete'")` | 语义等价 |
| `driver.get(url)` | `page.goto(url, wait_until='domcontentloaded')` | |
| `driver.current_url` | `page.url` | |
| `driver.title` | `page.title()` | |
| `driver.quit()` | `context.close()` + `browser.close()` | |
| `switch_to.window_handles` | 会话内 `pages` 列表 + `current_index` | |
| `window.open()` | `context.new_page()` | |
| `driver.find_element(By.XPATH, "//button[contains(text(),'登录')]")` | `locator("xpath=//button[contains(text(),'登录')]")` | 登录按钮查找策略逐条保留 |

### 2.3 线程模型

- Playwright 为异步 API，且其对象绑定创建它的事件循环线程。
- 方案：新增 `appcore/automation.py`，内部启动**专用自动化线程**并在其上运行 asyncio 事件循环；
  GUI 线程通过 `run_coroutine_threadsafe` 投递协程并等待结果。
- 所有 `QRunnable` 任务（设备加载 / 快捷登录 / 分组登录 / 关闭浏览器）都通过该通道执行，
  **界面主线程不会被浏览器操作阻塞**（界面测试中分组登录期间界面仍可响应）。

### 2.4 固定延时的处理

| 原位置 | 原写法 | 新写法 |
|--------|--------|--------|
| 访问 URL 后 | `time.sleep(2)` | `wait_until='domcontentloaded'` + `readyState==='complete'` |
| 输入用户名/密码后 | `time.sleep(0.3)` | 直接使用 `locator.fill()`（自动等待） |
| 点击登录后 | `time.sleep(2)` | 轮询页面真实状态判定（`LOGIN_RESULT_TIMEOUT=12`） |
| 验证码等待 | `time.sleep(2)` | 定位后等待人工输入（不再固定等待） |
| 标签页切换 | `time.sleep(1)` | 会话内索引切换，无延时 |

## 3. GUI 侧变更（PyQt6 保持不变）

- 框架仍是 **PyQt6 + qfluentwidgets**，未引入 Tkinter / Web。
- 控件、菜单、文案、布局、双击交互全部保持原样。
- 变化点：
  1. 浏览器操作全部改为「后台任务 + 信号回传」，界面不再因浏览器操作而卡顿。
  2. 退出流程补全：`thread_pool.waitForDone` → 关闭全部浏览器 → 停止 Playwright 驱动 → `app.quit()`。
  3. 窗口图标改为多路径解析（随包资源目录 → EXE 同目录 → 内嵌 base64 兜底），
     解决 PyInstaller 单文件模式下图标路径问题。
  4. 修正 `template_recorded` 信号类型（`pyqtSignal(str, str)` → `pyqtSignal(str, object)`），
     修复「登录成功后保存模板」回调不触发的问题。
  5. 修正 `stat_label.setFont = ...` 笔误为 `stat_label.setFont(...)`。
  6. **登录日志落库修正**（测试阶段发现的缺陷）：
     - `login_engine.login_group()` 在每台设备登录完成后再回调一次带 `✓/✗` 前缀的结果消息，
       使界面能区分「登录中」过程行与「登录结果」行；
     - `LoginWindow.add_log()` 新增 `record_db` 参数，「登录: 设备X」过程行只上屏、不入库；
     - `_on_progress_updated()` 按前缀解析设备名，并用 `_find_device_url()` 从当前设备列表回填 URL；
     - 结果：`login_logs` 表中单设备记录的 `device_name` / `url` / `status` 均正确。
       （原行为：单设备记录一律 status=「失败」且设备名与 URL 为空）

## 4. 关键实现差异（兼容性适配）

| 项目 | 原实现 | 新实现 | 原因 |
|------|--------|--------|------|
| SSL 处理 | 访问 `https://www.baidu.com` 触发证书错误再跳回原 URL | `ignore_https_errors=True` + 检测 interstitial 文本并点击「高级/继续」 | 原实现依赖外网、会丢失页面状态 |
| 登录成功判定 | 点击登录按钮即返回成功 | 表单消失 / URL 变化 → 成功；页面出现错误提示 → 失败；超时 → 未确认 | 原实现存在误报 |
| 已登录检测 | 无 | 新增 `_looks_logged_in()`，登录页 URL/标题关键词优先判断 | 避免把登录页误判为已登录 |
| 浏览器路径 | 依赖外部 ChromeDriver | `PLAYWRIGHT_BROWSERS_PATH=0`，浏览器随包内置 | 打包要求 |
