# 模板维护说明

本说明面向使用者：如何在**不修改任何 Python 代码**的前提下，维护本工具的登录模板。

---

## 1. 模板目录在哪里

| 运行方式 | 模板目录 |
|----------|----------|
| 源码运行（`python main.py`） | `<项目根目录>\templates\` |
| 打包 EXE 运行 | `<EXE 所在目录>\templates\` |

程序只有一个模板目录，**不存在多个候选目录的优先级问题**。

> 重要：模板目录位于「可写数据目录」，**不是** PyInstaller 的 `_MEIPASS` 解压目录。
> 因此 EXE 每次启动都不会重置模板，用户在模板目录里的修改会被完整保留。
> `templates/` 目录不随 EXE 打包内置，首次运行时由程序按需创建。

界面内可直接打开该目录：**工具 → 管理模板文件**（会同时重新加载磁盘上的模板）。

---

## 2. JSON 格式

一个模板文件就是一个 JSON 对象：

```json
{
  "name": "模板名称",
  "description": "模板说明",
  "username_selectors": [
    { "by": "css", "value": "input[name='username']" }
  ],
  "password_selectors": [
    { "by": "css", "value": "input[name='password']" }
  ],
  "login_button_selectors": [
    { "by": "css", "value": "button[type='submit']" }
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | 建议填 | 模板名。设备配置的「模板」列按此名称引用；不填时用文件名（去掉 `.json`） |
| `description` | 否 | 备注说明，程序不解析 |
| `username_selectors` | **是** | 用户名输入框的候选定位器，按顺序尝试，命中即停 |
| `password_selectors` | **是** | 密码输入框的候选定位器 |
| `login_button_selectors` | 否 | 登录按钮的候选定位器；为空时使用内置通用登录按钮查找 |

### `by` 支持的定位方式

| 写法 | 含义 | 生成的 Playwright 选择器 |
|------|------|------------------------------|
| `NAME` | 按 name 属性 | `[name="值"]` |
| `ID` | 按 id 属性 | `[id="值"]` |
| `CLASS_NAME` | 按 class（含空格分隔的多值） | `[class~="值"]` |
| `XPATH` | XPath 表达式 | `xpath=表达式` |
| `CSS_SELECTOR` / `css` | CSS 选择器 | 原样使用 |
| `TAG_NAME` | 标签名 | 原样使用 |
| `LINK_TEXT` | 链接/按钮文字（完全匹配） | `get_by_text()` |

> 大小写不敏感：`css`、`CSS_SELECTOR`、`Css_Selector` 都会被识别并归一化为 `CSS_SELECTOR`。

### 注意事项

- `value` 不能为空，否则该条选择器会被忽略。
- `username_selectors` / `password_selectors` 为空时，模板仍可加载，
  但登录时对应部分会自动回退到通用元素查找（日志中会给出提示）。
- 选择器按**列表顺序**尝试，因此把最精确的放在最前面可以加快登录。

## 3. 如何新增模板

1. 复制一份现有模板，例如把 `templates/proxmox.json` 复制为 `templates/pfsense.json`。
2. 用记事本 / VS Code 打开新文件，修改 `name`、`description` 与三组选择器。
3. 保存为 **UTF-8** 编码的 `.json` 文件。
4. 回到程序，点击 **工具 → 管理模板文件**（会自动重新加载并弹出已加载的模板列表）。
   若程序未运行，重启程序即可生效。

不需要重启的前提是使用「管理模板文件」触发重载；直接改盘后未重载时，下次启动程序会加载。

---

## 4. 如何修改模板

- 直接编辑 `templates/<名字>.json`，保存后用「工具 → 管理模板文件」重载，或重启程序。
- 程序**不会**在启动时覆盖已存在的模板文件，你的手工修改一定会被保留。
- 若模板 JSON 语法错误：该文件会被跳过并在日志中给出文件名与原因，**其它模板照常可用**。
- 若模板缺少字段或选择器非法：该文件仍会加载，非法选择器被丢弃并在日志中提示。

## 5. 设备如何引用模板

在设备配置（`devices.json`）或 Excel 模板的「模板」列填写模板名：

```json
{
  "name": "fnOS测试机",
  "url": "http://192.0.2.11",
  "username": "admin",
  "password": "******",
  "group": "内网设备",
  "template": "proxmox"
}
```

- 留空或填 `default` → 使用内置通用模板（`templates/default.json`）。
- 填模板名 → **优先使用该模板**查找用户名框、密码框与登录按钮。
- 填了不存在的名字 → 日志中明确提示「模板不存在」，并回退到内置通用模板，
  **不会**静默套用其它模板。

## 6. 模板优先的执行顺序

登录时的实际执行顺序（`appcore/login_engine.py` → `appcore/browser.py`）：

```
设备配置.template
      │
      ▼
TemplateManager.get_template(名称)      ← 校验通过才返回
      │                                     失败 → 记录原因 + 回退内置通用模板
      ▼
find_by_selectors(用户名选择器)         ← 只查模板，不做通用扫描
      │ 命中 ──────────────────────────► 直接使用
      │ 未命中
      ▼
find_username_field()  通用发现        ← 仅在模板失效时执行
```

密码框、登录按钮同理（登录按钮由 `click_login_button(selectors=...)` 优先使用
模板的 `login_button_selectors`）。

## 7. 如何验证模板是否生效

1. **看日志**：程序在 `app.log` 中记录
   - 「使用模板 'xxx'（模板文件: …）」→ 模板已被取用；
   - 「模板密码选择器未命中，回退到通用密码框查找」→ 模板选择器失效，需更新 JSON。
2. **看界面**：登录成功后界面日志会显示实际执行结果。
3. **自动化验证**：执行 `python tests/test_templates.py`，其中包含
   「有效模板优先于通用发现」「模板失效回退」「多设备各用各的模板」等断言。

## 8. 录制并保存模板（界面内操作）

1. 正常完成一次登录（快捷登录或分组登录均可）。
2. 登录成功后程序会询问是否保存为模板；也可以随时用 **工具 → 保存登录模板**。
3. 输入模板名 → 确认。
   - 若同名模板已存在，程序会先弹出「是否覆盖」确认框。
   - 保存采用**原子写入**（先写临时文件再替换），失败时不会留下损坏文件，
     且界面会明确提示失败原因（可在 `app.log` 中查看细节）。
4. 保存成功后模板立即进入内存注册表，**下一次登录同一台设备就会真正使用它**。

## 9. 常见问题

| 现象 | 原因与处理 |
|------|------------|
| 提示「模板文件解析失败 xxx.json」 | JSON 语法错误，用 VS Code 打开检查括号与引号 |
| 模板能加载但登录仍走通用查找 | 模板的选择器与目标页面不匹配，用浏览器开发者工具确认真实属性后更新 JSON |
| 提示「模板 'xxx' 不存在或未通过校验」 | 名称拼写错误，或该文件解析失败；用「管理模板文件」查看实际已加载的模板名 |
| 保存模板失败 | 检查模板名是否含 `\ / : * ? " < > |`，以及模板目录是否可写 |
| 修改模板后没生效 | 执行「工具 → 管理模板文件」重载，或重启程序 |
